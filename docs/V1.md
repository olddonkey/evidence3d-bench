# Evidence3D v1：先有真值，再生成资料

v0 的问题是：能自动评分的题把完整参数表直接给了模型（抄写题），考"从资料还原"的真实照片题又没有真值、没有坐标系，评不了分。v1 把出题顺序反过来：

1. 先由参数化生成器造出一个**隐藏的真值模型**。
2. 再把它**渲染成资料**：街景照片、航拍、带比例尺的图纸、勘测笔记。参赛模型只看到这些。
3. 提交的 GLB 与真值比较，**全自动、连续值**评分，并把"坐标／尺度误差"与"形状误差"分开。
4. 同一对象出多档资料，外加一道图纸过期的冲突题，用几何结果判断模型有没有正确使用证据。

被测能力：给定资料，建出尺寸和结构正确的 3D 模型，依据的是资料而不是记忆。

工程契约（数据格式、模块接口、评分定义）在 [v1/DESIGN.md](../v1/DESIGN.md)。v0 的代码、测试和文档保持不变，仍可用作评分器回归和人工盲评工具。

## 题目

对象由 `v1/lib/generator` 按种子生成，五类：住宅、单层商业、多层塔楼、带塔的砖石大厅、工程结构（水塔、气柜框架、碟形天线）。种子改变的是结构（层数、开间数、有无塔楼和加建），不只是比例。每个对象都有左右和前后不对称，镜像能被检出。

每个对象渲染一整套资料，再按题型取子集：

| 题型 | 给的资料 | 尺度 |
|---|---|---|
| `t1` | 一张正面街景照片 | 不确定，按形状评分（允许整体缩放） |
| `t2` | 四张照片（正、左前、右前、后）加航拍 | 不确定 |
| `t3` | t2 加平面图、正立面和右立面，带比例尺 | 有 |
| `t4` | t3 加写有具名尺寸的勘测笔记 | 有 |
| `c1` | 同 t3，但图纸画的是建筑的早期状态（日期更早），任务要求还原照片拍摄时的状态 | 有 |

照片由 Blender 路径追踪渲染，有天空、地面、阴影、树木、车辆和电线杆遮挡。图纸和笔记是位图和文本，不提供任何可解析的参数。坐标系写在题面里：米制、+Y 向上、正面朝 +Z、原点在正面墙底边中点。

## 评分

设 D 为真值包围盒对角线。完整定义见 DESIGN.md 第 9 节，说明见 [v1/lib/score/README.md](../v1/lib/score/README.md)。

- **有效性门槛**：GLB 不合规记 0 分。
- **可见表面采样**：从 25 个固定方向渲染，只比较最外层可见表面，内部几何既不奖也不罚。
- **证据覆盖**：真值表面只有被给出的照片或立面图实际拍到（考虑遮挡物和掠射角）才计分。没有证据的表面不计分。
- **对齐**：平移和绕竖轴旋转总是拟合；尺度只在资料不含尺度时拟合。拟合量作为 `frame_error` 单独报告。
- **形状分** `shape_score`：在 1%、2%、5% D 三档容差下的 F-score 取平均，再乘 100。
- **细节分** `detail.score`：按真值的部件分组（门窗、入口、雨棚、屋顶、结构杆件……）逐组评分，容差取该组最小特征尺寸的 0.6 倍，评分前允许不超过 2% D 的局部平移。
- **主分** `score = (shape_score + detail.score) / 2`。只看表面重合的话，一个包围盒在板式高楼上能拿 82 分；细节分是区分"建了这个对象"和"围了个盒子"的部分。
- **探针**：预设射线量出具名尺寸（屋脊高、墙位置、雨棚高），报告米制误差。
- **冲突题**：对争议探针判断测量值更接近当前状态还是早期状态。
- **颜色**（次要）：匹配点的基础色 ΔE，贴图不计。

## 评分器校准

在五道真实题上对真值做缺陷注入（`node v1/cli.mjs calibrate --task ID`），175 行里 168 行符合预期：

| 提交 | 主分 |
|---|---|
| 真值本身 | 99.9–100 |
| 改名、改色、重新细分、整体平移或旋转 | 不变，偏移量出现在 `frame_error` |
| 有尺度的题上放大 5% / 10% / 20% | 80–82 / 59–61 / 36–57 |
| 无尺度的题上放大 20% | 不变 |
| 只有包围盒 | 19–46 |
| 左右镜像 | 低 27–53 分 |
| 好模型加一块地面 | 低 28–45 分 |
| 只建正面的薄壳，四面都有照片时 | 低 40–52 分 |

未达预期的 7 行：整块删掉屋顶、主体或塔身这类大结构时，邻近细节组的得分会漂移 0.1–0.47；镂空结构的单照片题上，只建正面的薄壳被扣了 7.6 分（背面杆件能透过空隙看到）。这些情况在 `calibrate` 输出里以 FAIL 行保留。

## 运行

要求 Node.js 22.2 以上，渲染照片需要 Blender 5.x（默认 `/Applications/Blender.app`）。

    npm ci --ignore-scripts
    npm run test:v1

生成题目（开发集的种子公开；测试集的种子文件不要提交）：

    node v1/cli.mjs build-set --set v1/sets/dev.json
    node v1/cli.mjs verify

评分与校准：

    node v1/cli.mjs score --task house-0011-t2 --glb /path/to/model.glb --out /tmp/report
    node v1/cli.mjs score --task house-0011-t2 --glb truth
    node v1/cli.mjs calibrate --task house-0011-t4

让模型作答（隔离运行，详见 [v1/lib/runner/README.md](../v1/lib/runner/README.md)）：

    node v1/scripts/run.mjs prepare   --id BATCH --system codex --model gpt-6-astra --effort high --tasks a,b,c
    node v1/scripts/run.mjs preflight --batch .local/v1/runs/BATCH
    node v1/scripts/run.mjs run       --batch .local/v1/runs/BATCH --concurrency 2
    node v1/cli.mjs report --batches BATCH1,BATCH2 --out .local/v1/reports/NAME

`--system` 支持 `codex` 和 `claude-code`。评分定义改动后，用 `node v1/cli.mjs rescore --batches …` 对已保存的提交重新评分，不会重新生成。

## 运行条件与隔离

- 每题一个全新会话，工作目录里只有题包、three.js、一个预览工具和空的输出目录。
- 预览工具 `tools/preview.mjs` 由题面提供，把模型自己的 GLB 渲染成 PNG，不含任何评分逻辑。
- 文件和网络边界由各 CLI 自带的 Seatbelt 沙箱实现，运行前用真实探针验证：题包只读、输出可写、仓库和真值不可读、用户记忆和登录信息不可读、本地和外部网络不通。预检不通过就不运行。
- 墙钟上限 30 分钟，超时杀掉整个进程树；token 和 CLI 估算的费用如实记录。
- 评分在参赛进程退出后、沙箱之外进行。

## 已知限制

- **比较的是"模型 + 客户端"**。两个 harness 的工具和内置提示不同；没有用 API 自建统一 agent 循环。
- **预算是墙钟**，不是 token：服务端推理速度会影响结果。
- **渲染资料比真实照片干净**。没有邻近建筑、电线、污渍和广角畸变，测到的更接近能力上限。
- **生成器的风格有限**，五类对象各一套构造规则。
- **图像渲染不是逐字节可复现的**（GPU 路径追踪加降噪）；相机、遮挡物和后处理参数可复现，题包一经生成即哈希锁定。
- **指标与人的判断是否一致尚未验证**。v0 的匿名 A/B 页面可用于这项研究，但还没有做。
- **没有真实建筑题**。用规划申请图纸做真值的真实题层还没有建。
- 边界只在 macOS 上实现和验证。
