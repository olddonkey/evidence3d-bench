# v1 首轮试点（2026-10-01）

目的只有一个：验证 v1 的分数能不能把模型拉开，并且和肉眼看到的质量一致。这不是正式排名：只有 5 个对象，每题一次作答，题目是种子公开的开发集。

## 条件

- 开发集 5 个对象（住宅、商业、塔楼、大厅、水塔各一个），每个对象 `t2`、`t4`、`c1` 三题，住宅和大厅另加 `t1`，共 17 题。
- 四个配置，各 17 次作答，每题一次，30 分钟墙钟上限：
  - Codex CLI 0.159.2：`gpt-6-astra`（high）、`gpt-5.6-luna`（high）
  - Claude Code 2.1.285：`claude-opus-5-5`（high）、`claude-haiku-4-5-20251001`（默认）
- 每批同时跑两题，四批并行，所以墙钟时间互相有干扰，不能当作速度比较。
- 四个批次的隔离预检全部通过，68 次作答没有一次触发完整性问题。
- 批次：`.local/v1/runs/pilot2-{astra,opus,luna,haiku}`；报告：`.local/v1/reports/pilot2/index.html`。

## 读法

- **分数拉开了**。强弱两组之间差 23–43 分，区间不重叠。Astra 和 Opus 的区间重叠，5 个对象、一次作答分不出这两者的先后。
- **分数和肉眼一致**。同一道题上把真值和四份提交并排渲染，质量顺序与分数顺序相同：Astra 和 Opus 的大厅模型与真值几乎一样，Luna 的塔楼比例和细节明显走样，Haiku 交的是没有门窗的体块。
- **形状分对强模型接近饱和**（97.7、95.0），区分度主要来自细节分。这说明 1%／2%／5% 的容差对强模型偏松，下一版可以收紧。
- **图纸的作用被量出来了**。强模型有了图纸后尺度误差降到 0.1–1.2%，主分升 19 分左右；Haiku 平均没有任何提升。
- **冲突题区分度最强**。图纸过期时，Astra 和 Opus 按照片建，Luna 和 Haiku 按旧图纸建。Opus 唯一一次失误是水塔的罐顶高度用了旧图纸的值。
- **弱模型的坐标系问题**。Haiku 有 4 次交付相对题面坐标系转了 80°–150°，评分时被对齐拟合掉并记在 `frame_error` 里。

## 这轮没有回答的问题

- 每题只跑了一次，没有稳定性数据。
- 5 个对象太少，Astra 和 Opus 的差异不可信。
- 没有 t3，资料阶梯只有 t2 → t4 一步。t2 − t1 不是干净的比较：t1 只评正面，t2 评四面。
- 四批并行，用时受机器负载影响。
- 指标和人的判断只做了肉眼核对，没有做盲评一致性研究。
- 比较的是"模型 + 客户端"，两个 harness 的工具和内置提示不同。
