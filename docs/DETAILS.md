# v0.2 视觉与细节评测

此文描述细节评分协议。应用 v0.3 增加多示例选择、独立索引和三组新对象，见 [EXAMPLES.md](EXAMPLES.md)；评分原则保持一致。

本版本把整体视觉、局部几何测量和人工细节评分作为三个独立结果。没有调用模型裁判，自动测量不产生人工 0–4 分。

## 可运行的验证

立面校准题包含四个有立体窗棂的窗、入口、拱券、檐口与齿饰、阶梯扶壁、玫瑰窗。十张卡片可评分，后立面装饰因未提供要求而预先排除。

十二个提交包含原样对照、改颜色、改名称、等价顶点表示，以及八种缺陷：缺窗棂、缺窗、额外窗、压平窗框、窗户错位、缺玫瑰窗内部框架、压平拱券和扶壁悬空。

这些缺陷保持实际整体包围盒相同。少一根竖窗棂时，全局轮廓 IoU 仍为 1；在左下窗的固定正面，约 2.78% 的有效像素深度发生超出容差的变化，固定斜视约为 4.17%。这说明全局轮廓不足以证明细节完整。

校准输入列出所有被测几何的参数，包括玻璃面深度、框架位置、装饰截面和曲线细分；软件测试用独立的局部深度探针核对其中的关键尺寸。该题检验有明确参数时的建模与评测行为，不是“从一张真实照片恢复未知尺寸”的能力测试。

## 细节卡片

每套卡片绑定 task_sha256、reference_sha256 和证据来源。卡片指定：

- 卡片 id、类别、类别内权重、是否可评分。
- 来源文件 id、具体要求与五个评分锚点。
- 策展方固定的相机原点、正交基、取景范围和分辨率。
- 事先确定的可见性忽略区域，以及几何测量容差。

候选不能根据自己的输出改变裁切、删掉难点或重分配权重。没有资料的部分由出题方预先排除；评审者对资料提出疑问时，记录为待核验而非零分。

JSON Schema 位于 schemas/detail-set.schema.json。真实卡片必须有 independent_review 来源、两位不同的核验者标识和证据。标识是人工审核声明，不是身份认证或自动可信证明。

## 自动测量

所有候选三角形应用其世界变换后进入固定相机的软件 z-buffer。每个像素取最靠近相机的表面，输出：

1. 覆盖 Precision / Recall / IoU。
2. 相同可见区域的平均与 95 分位绝对深度误差，单位为米。
3. 超过单像素深度容差的像素比例，用来发现面积小于 5% 的窗棂等细节。
4. 几何面法线平均角度差。

当前校准每卡片使用正面与斜视两个 144 × 144 视角。深度差与法线差只在双方均有表面的像素计算；缺失覆盖另行记录，空参考导致评测配置错误，不能得到满分。

相机和深度显示范围都来自参考。侧向移动、前后压平或缺失构件不会触发候选自动取景。数据没有使用节点名字或候选自报的部件清单。

每个视角导出参考深度、候选深度、深度差、参考法线、候选法线和覆盖对照 SVG。深度差图的紫色表示覆盖不同；它不是一个假设的深度数值。

当前阈值只用于解析校准：平均深度误差不超过 0.006 m、95 分位不超过 0.035 m、单像素深度容差 0.015 m、异常像素比例不超过 0.8%、平均法线角差不超过 2°、覆盖 IoU 至少 0.98。真实对象必须另行标定。

这些检查只描述指定视角下最前方的可见表面。内部、完全被遮挡的表面、重复重叠面、严格拓扑与封闭性仍未覆盖。法线朝向相机统一处理，因此不能据此判断面绕序。法线结果也受曲面细分影响，不能把几何检查通过直接解释成完整语义正确。

## 三维观察

局部工作台和逐项评审提供四种观察方式：

- 灰模与固定光照／阴影：观察实际凸出、凹陷与构件。
- 基础材质色块：保留固体颜色、金属度和粗糙度；当前不包含贴图写实评测。
- 几何法线：辅助观察轮廓转折和表面方向。
- 固定范围深度：辅助观察前后层次。

参考和候选共享视角、缩放与照明。正常浏览时可联动旋转和缩放，固定正面／斜视按钮回到卡片相机。全貌只用于定位，不产生新的局部测量结果。自动差异图始终对应指定的固定相机。

## 人工 0–4 分

逐项评分隐藏候选身份、条件标签和自动检测结果，展示参考、卡片要求、证据与锚点。每张卡片都有特定描述；例如窗户：

- 0：缺失或完全错误。
- 1：只有平面占位或外框，窗棂和立体层次缺失。
- 2：主要形态存在，但缺窗棂、明显错位或压平。
- 3：位置、四边框和十字窗棂正确，仅有次要偏差。
- 4：形态、位置、比例与凸出厚度满足卡片全部要求。

评分者也可以申请资料核验，但必须记录原因。零分、未填写与资料不足是不同状态。练习记录永久排除在人类结果之外；自动化测试仅使用临时目录或明确标识的练习模式。

每人每候选每卡片只计一次。可使用同一昵称继续下一个候选，避免通过改昵称虚增独立评审人数。昵称只是本地标识，正式研究仍需独立身份和招募管理。

## 汇总

先在每个类别内按卡片权重取平均，再按预先固定的类别权重汇总成 0–100。立面校准目前采用门窗、入口、构造、装饰四类等权。权重是校准配置，不是已经验证的行业标准。

任何必需卡片缺少评分时不重分配其权重，总分为 null。每张卡片至少三位独立评审后才可进入多人汇总；评分范围达到 2 分或存在资料争议时，标记 needs_adjudication，总分仍为空。软件不会自动替人解决分歧。

完整的一轮个人评分可以显示个人练习或个人评分结果，并明确不属于多人结论。多人卡片均分允许小数，原始个人评分只能为整数 0–4。

添加一个候选不会改变已有任务／卡片的实验身份；旧评分可继续使用。改变来源、坐标、真值或卡片会形成不同实验，旧评分保留而不混算。

## 整体视觉 A/B

原有 A/B 评审增加三个目标，分开记录、分开汇总：

1. geometry_fidelity：灰模几何忠实度。
2. appearance_fidelity：固定灯光下的整体形态与基础材质忠实度。
3. aesthetic_preference：整体审美偏好。

审美偏好不会自动成为还原准确性。反向位置复测、平局、两个都不好和资料不足继续保留。不存在将三种目标混算的综合榜。

## 真实建筑草案

七个真实对象各有十张局部参考草案，保存在 .local/annotations/details-TASK.json，界面显示对应的原图区域。草案经过源图查看，但尚未独立确认，所有卡片均为不可评分状态，world_camera 和 thresholds 为空。

视角误差、树木／人群遮挡、玻璃反射、拍摄年代和无法从单图确定的进深需要分别核验。草案生成器保留已有人工修改，不会自动把这些草案升格为真值。

## 命令

    npm run demo:details
    node cli.mjs pack --task .local/tasks/calibration-facade-v1/task.json --out exports/calibration-facade-v1
    node cli.mjs submit --task .local/tasks/calibration-facade-v1/task.json --artifact /path/to/run/model.glb --id model-a-01 --seconds 420 --model exact-model-version --harness exact-harness-version --human false
    node cli.mjs register-detail --submission /path/to/run/submission.json --label "Model A / run 1"
    node cli.mjs detail-summary

示例中的耗时、版本和人工介入字段须填写实际值。登记只接收已生成的 GLB，不调用模型；运行预算仍为自报，隔离生成 runner 尚未实现。
