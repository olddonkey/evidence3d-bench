## 1. Round 4 要回答什么

**主问题**：在一个评分器冻结之后才生成的新私有题集上，各个**系统**（客户端 + 模型 + 推理档位）从资料建 3D 模型的排序，以及榜上每个分差是否可信。每个分差要能回答三件事：

1. 校正多重比较之后是否仍然分开（第 4 节）；
2. 人眼能不能看出这么大的差（第 6 节）；
3. 有多少可能来自客户端而不是模型（第 5.3 节）；量不出来时，明确声明这是系统榜。

**次要问题**，怎么报都在这里先定好：资料阶梯的增量（含新题型 `t5`）；照片退化 `p1`–`p3` 的代价；真实建筑层的成绩与"合成 → 真实"的落差；分数-时间曲线；与 Round 3 的回归对照。

**不回答**：纯模型之间的比较（不用 API key，`api-anthropic`、`api-openai` 不跑）；记忆题（`memory-2026-10` 只有 4 个对象，不进 Round 4）；可编辑性和网格质量（R10，以后再做）。

## 4. 统计：什么叫"分开"

沿用 Round 3 和 `v1/lib/report/README.md` 的定义，只加多重比较校正：

- **主分**：题内多次作答取均值 → 对象内对题取均值 → 对象之间取均值；95% 区间是按对象的百分位自助法。无效交付记 0；排除状态（`infra_error` 等，`DEFAULT_EXCLUDED_STATUSES`）不进任何均值。完整性问题记 0，从不当作基础设施错误。
- **两两比较**：每个对象上取两个系统在双方都有的题上的分差，做配对自助法 95% 区间（10 000 次）和配对 t 区间。
- **分开** = 未校正时已经分开（自助法区间和 t 区间都不含零），**且**配对 t 检验的双侧 p 值经 Holm 校正后 < 0.05（α = 0.05）。未校正的两个区间照样并排给出。
- **Holm 家族**，每个题集分开算，每张表写明 m：
  - 默认档榜的全部两两比较，一族；
  - 最高档榜的全部两两比较，一族；
  - 同一 system + model 的 `max` − `high`，一族；
  - 真实层榜的全部两两比较，一族；
  - 附加题型相对各自对照的增量（`t5`、`p1`–`p3`、`t1` 对 `t2`，难图纸对 `t3`），按"系统 × 题型"一族。
  - 少于 2 个对象、无法检验的对不计入 m。同模型跨客户端对照只有一个预先指定的比较，不校正。
- **结论以两张榜各自的家族为准**。报告里"全部正式配置"的总表也做 Holm（家族是该题集所有正式配置的两两比较，m 更大），同一对在两张表里可能结论不同；总表只作补充，跨榜的配对（如某系统 `max` 对另一系统 `high`）只在总表里出现。
- **判定用语**与报告的 `verdict` 一致：分开 / 未分开 / 不一致（两种区间的结论不同）/ 无法评估。
- **预期分辨率**。按 Round 3 的方差粗算：同题作答 SD 约 4.8；两个强配置之间每对象配对差 SD 3.5–4.4，其中作答噪声约 5 分²。72 个对象、每题 1 次时，配对差 SD 约 4.7–5.4，未校正以 80% 把握能检出约 1.6–1.8 分，Holm 最严的一步（默认档榜 5 个系统，10 对）约 2.1–2.3 分。报告的 `PLANNED_OBJECTS` 改为 72 后，投影按这个规模算。

## 5. 阶段 2 的判定规则

结果写进私有记录，再在第 14 节记一条。

### 5.1 评审者（T9）

- 至少 3 位评审者，各自评完同一份 110 对（100 对原始对 + 10 对左右互换的重复对）。评审者有空间感，没参与过本项目，没看过任何提交、分数或报告。
- **合格**：评完 110 对，且 10 对重复对中至少 7 对前后选择一致（"分不出"也算一种选择）。不合格的评审者单独报告，不进多数票。
- **多数票**：每对取合格评审者的多数（A / B / 分不出）。3 人各不相同记"分不出"。只剩 2 位合格评审者时，两人一致才算有决定，否则记"分不出"。只剩 1 位时不做 G1，保留 1.1.0，报告写明。

### 5.2 G1：主分的权重（评分器 1.1.0 还是 1.2.0）

- **一致率 A(s)**：在多数票为 A 或 B 的原始对上，多数选中"分数 s 更高的那一份"的比例，附 Wilson 95% 区间；s 相同（差 < 0.05）的对不计。对五个 s 各算一次：主分（形状 50 / 细节 50）、形状分、细节分，以及两个候选权重：形状 65 / 细节 35、形状 35 / 细节 65。
- **规则**：两个候选权重里，一致率高于 50/50 的那个，若在它与 50/50 排序不同的那些对上做 McNemar 精确检验（双侧）得 p < 0.05，就改用它，评分器升为 1.2.0；两个都满足时取一致率高的。否则保留 1.1.0。
- 另外，50/50 的一致率区间下界若 < 70%，不论改没改权重，Round 4 报告的主分一节都要写明"主分与人眼的一致率低于 70% 的目标"，并附曲线。
- **为什么不用路线图草案的规则**（"下界 ≥ 70% 且不低于形状分、细节分各自的一致率，否则换成一致率最高的权重"）：100 对里大约 80 对会有决定，差一两对就能翻转"不低于"；而改权重要 rescore 约 2000 次作答、改三份文档，必须是检验得出的差。按这个规模，新规则多半会保留 1.1.0，这正是 100 对能支持的结论。
- **若改**：只改权重，容差、分组、对齐都不动，校准测试全跑；在 M3 之前 rescore Round 3 的全部作答，更新 V1-TEST、V1-ROUND3 和架构页的数字。

### 5.3 G2：同模型跨客户端对照（替代 R3）

- **是否存在**：某个模型在两个订阅客户端里都能跑，例如 Claude Opus 5.5 同时在 Claude Code 和 Antigravity 里。以客户端的模型清单（`agy models` 的输出原样存进私有记录）和会话自报的 `model_reported` 为证。有多对时先做 Opus 5.5（Claude Code 一侧有 Round 3 的三次作答和重测），其次 GPT。
- **档位**：两边都用 `high`；某一边不接受 `high` 时两边都用各自的默认档，并写明量到的是"客户端 + 默认档"的效应。
- **设计**：`test-2026-10` 的 72 道主题，**两个客户端都新跑**各 1 次：同一台机器、同一周、同一个 Node 和运行器提交、并发 1。Round 3 的行只作第二个估计和漂移检查。两边都新跑的理由：Round 3 的 Opus 行是三周前、用另一个 CLI 版本、可能在另一台机器上跑的，新旧混配会把时间和工具链的漂移算进客户端效应。代价是多 72 次作答（Opus 中位约 4 分钟，半天左右）。
- **估计**：每个对象上 B − A（对象内三道题的均值），配对自助法和 t 区间；另报各题型的差、撞上限的比例、中位用时、有效交付数。
- **怎么上榜**：有对照时，报告写"同一模型换客户端差 Δ [lo, hi]"，并把 max(|lo|, |hi|) 当作尺子：跨客户端的两个系统之间小于这个数的差，标注"可能全部来自客户端"。没有对照时，榜单上方写这句话：

  > 本榜每一行是客户端 + 模型 + 推理档位的组合。不同客户端之间的分差包含客户端的作用（工具、内置提示、上下文管理、超时时的行为），不能归到模型本身。

## 6. 人眼曲线怎么进榜

- **曲线**：盲评的四个分差档 [0, 3)、[3, 8)、[8, 15)、[15, 100] 上，多数票选中高分方的比例，附 Wilson 区间，报告里画出来。这条曲线来自 Round 3 的作答，Round 4 沿用，前提是"分差多大人眼能分辨"不随题集而变；报告写明这个前提。
- **每一对比较加一栏"人眼偏好 A 的预期比例"**：对两个系统都有的每道题，按题上分差 g 的绝对值查所在档的 p（p = 该档原始对中，多数选高分方的对数加上多数为"分不出"的对数的一半，除以该档对数），g > 0 取 p，g < 0 取 1 − p，然后先在对象内对题平均，再对对象平均。之所以按题算，而不拿平均差去查曲线：榜上平均差 2 分，不等于每道题都差 2 分。区间用按对象的自助法；曲线本身的不确定性不传递，报告注明。
- 不另设"能分辨 / 不能分辨"的阈值，报告给数字和区间。

## 7. 分数-时间曲线（T6）

- 墙钟上限仍为 30 分钟，与 Round 3 相同。快照间隔 300 秒，在 `prepare` 时冻结进 manifest；主分只看最终文件。快照时钟从 CLI 进程启动算起，只取小于墙钟上限的刻度（`t300` … `t1500`），最终文件就是结束时刻的那一点。
- **每次作答在刻度 T 的分数**：作答已结束或 T 到达墙钟上限，取最终分；否则取 T 之前最后一个快照的分，那时还没有 `model.glb` 或文件无效的，记 0。
- **聚合**与榜单相同（作答 → 题 → 对象 → 对象均值，按对象自助法区间），所以 1800 秒那一点正好等于榜上的主分。`infra_error`、`score_error` 照榜单排除；某个快照评分出错记 0 并单独计数；边界被破坏的作答整条曲线为 0。
- **到达最终分 95% 的中位时间**：每次作答取第一个分数 ≥ 0.95 × 最终分的快照的刻度时间（最终文件算在 `wall_seconds` 时刻），对作答取中位数；最终分 < 10 的作答不进中位数，单独计数。
- 报告同时给撞上限的比例。曲线在 10 分钟、20 分钟处的值只作描述，不另排名次。
- **机器时间**：快照在主分之后依次评分，与更早快照或最终文件哈希相同的直接沿用分数；并发 1 时在下一次作答开始之前评完，不与参赛进程重叠。每个文件 25–100 秒，30 分钟的作答最多 5 个不同的快照，每次作答多 0–8 分钟机器时间。

## 8. 运行条件

- **一台专用机**跑全部正式批次（回归、同模型对照、主榜、真实层、附加题型）：插电、不合盖、不跑别的项目。是哪台机器写进私有记录（第 13 节）。如果某个客户端只能在另一台机器上跑（例如 Antigravity），它的行在报告里标注机器，且同模型对照的两个客户端必须在同一台机器上跑。
- **整机并发 1**：任何时刻机器上只有一次作答在跑。一个批次等配额重置时，可以停下它（Ctrl-C），先跑另一个系统的批次，之后再续跑；两个批次不同时跑。（V1.md 和 ANTIGRAVITY.md 的示例用并发 2；Round 3 的批次若用了并发 2，回归对照的差里也含这一项，报告注明。）
- **负载**：运行器已为每次作答记录 1 分钟负载（`load_1m`）。不按负载剔除作答，那是看过分数之后的分叉；报告另给一个敏感性分析：去掉负载均值超过逻辑核数的作答之后的主分。
- **主机睡眠规则**、`infra_error` 的定义和重跑（`--max-reruns 5`）都不变。
- **订阅与配额**：不用 API key；Antigravity 的 `useG1Credits` 保持关闭；批次中途不开启任何付费额度。批次尽量排在配额周期的开头。V1-TEST 里 Claude 订阅在约 200 次 Opus 作答时触到周限额，而 Round 4 在 Claude Code 一侧约有 620 次作答，Opus 若进附加题型的前 3 名则约 1000 次，所以配额而不是机器可能决定日程，排日程时先算这一项。
- **顺序**：回归对照先跑，然后主榜按第 2 节的优先顺序，然后真实层，最后附加题型。
- **时间窗**：主榜的全部批次尽量在 6 周内跑完，缩短模型在服务端被更换的窗口（Round 3 的 Opus 重测：9 天内没有可测的变化）。

## 9. 工具链冻结

Round 3 期间工具链在批次之间变了五次（V1-ROUND3 第 8 节）。Round 4 的规则：

- **专用 Node**：nodejs.org 的官方 macOS 安装包解压到专用目录，不经 Homebrew；版本在 M2 定。所有批次都用它的绝对路径启动 `v1/scripts/run.mjs`（运行器冻结的是 `process.execPath`）。各 CLI 的沙箱要能读这个目录，先用它跑一次 preflight 证明。
- **CLI 钉住**：每个客户端的版本在 M2 定下。把那个版本的程序复制到专用目录，用 `--binary` 或 `E3D_*_BIN` 指过去，让交互使用（包括在这台机器上开的远程控制会话）触发的自动更新碰不到它；各 CLI 自己的自动更新也关掉。能不能从副本运行，由 preflight 证明。怎么关的、版本号和哈希，写进私有记录。
- **批次期间不 `brew upgrade`**；Homebrew 的自动更新关掉（`HOMEBREW_NO_AUTO_UPDATE=1`）；macOS 的自动更新推迟到 Round 4 之后。
- **每次停顿后预期要重新冻结**：批次因 `frozen` 停下时，先在私有记录里写明变了什么。能恢复原样就恢复，续跑同一批次；不能就为剩下的题准备一个同系统的新批次（Round 3 的做法），报告会标出这个系统的批次不一致。已有样本的作答不重跑。
- 每个批次的 CLI、Node、运行器版本都在 manifest 里，报告标出不一致。
